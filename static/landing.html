Engine API

Built for agents, not just humans.

Every workbook is reachable over HTTP. Evaluate formulas, peek at cells, fetch a schema — your agent gets a typed, deterministic spreadsheet runtime instead of brittle screen-scraping.

  • POST /v1/eval — run a formula or batch of cells
  • GET /v1/schema — workbook structure + cell types
  • GET /v1/peek — read any cell, follow refs across sheets
  • Long-lived gridos_live_sk_ keys, scoped per workbook

FAQ

Common questions.

How is GridOS different from Excel or Google Sheets?

A chat that types directly into cells, a Python plugin runtime, and an HTTP API for agents. The grid still feels like a spreadsheet — but every cell can be driven by an LLM, an agent, or a custom formula you wrote yourself.

What does "BYOK" mean?

Bring Your Own Key. Paste a Gemini, Anthropic, Groq, or OpenRouter key into Settings; we proxy your prompts directly to that provider. We never see your tokens, and you never get a surprise GridOS bill for LLM usage.

Do you train on my data?

No. Workbooks are stored in Supabase under your account. Prompts go to whichever LLM provider you connected — we route, never retain for training.

Can I self-host?

Yes. The kernel is MIT-licensed. git clone, pip install, uvicorn main:app — that's it. SaaS-only features (auth, billing, marketplace) are clearly fenced.

What models are supported?

Gemini 2.5 Flash/Pro, Claude Opus/Sonnet/Haiku, Groq's Llama family, and anything reachable via OpenRouter — including Mistral, DeepSeek, and Qwen.

Is there an API for agents to use?

Yes. The Engine API exposes /v1/eval, /v1/schema, and /v1/peek behind long-lived gridos_live_sk_ keys. Agent frameworks can drive workbooks programmatically.
